Fix: values read from a contract are now validated against the contract's ABI before the SDK uses them, and the SDK's own contract calls are checked against the ABIs at compile time.

The transactions the SDK builds are byte-for-byte the same, and no documented API changes. Six things you could observe do change:

- **A malformed read now fails cleanly.** When a node, or a custom adapter, returns a value that does not match the contract's ABI, the call rejects with `BridgeEventDecodeFailedError`, whose `info.field` names the method and the output: `<method>.<output name>`, or `<method>.<index>` when the ABI leaves the output unnamed. Before, such a value could surface as a `TypeError`, a `SyntaxError` or a different SDK error, or be used as it was. A read now returns the same value on viem, ethers v5 and ethers v6, and a boolean read, such as an exists or approval check, accepts only a real boolean.
- **Some SDK errors no longer follow a malformed read.** `InvalidTokenTypeError`, `UntrustedPredicateError`, `InvalidHexStringError` (from the deposit-status read), `ExitQueueEmptyError`, `ExitGasLimitTooLowError` and `BurnTxNotCheckpointedError` could previously surface because a contract returned malformed data; they now surface as `BridgeEventDecodeFailedError` in that case. Each is still thrown for its real condition, which is unchanged.
- **A custom `Adapter` sees a `bigint` for a few arguments.** Nothing on the wire changes (the calldata is identical on all three libraries), but `ReadRequest.args` and `WriteRequest.args` now carry a `bigint` where they carried a string or a number: the checkpoint id passed to the root chain's `headerBlocks` (three call sites), the index passed to an ERC-721 `tokenOfOwnerByIndex`, the `v` of the staking permit, and the amount passed to the gas swapper's `swapAndBridge`.
- **An ERC-721 index or a permit `v` that is not an integer is rejected up front.** `getTokenIdAtIndexForUser` and the staking `delegateWithPermit` and `prepareDelegateWithPermit` now reject a value that is not a non-negative safe integer (a fraction, `NaN`, `Infinity`, a negative number, or one past `Number.MAX_SAFE_INTEGER`) with `InvalidNumericValueError` before any request is sent. Before, the value was passed to the web3 library, which either failed with its own error or encoded a different number.
- **The gas swapper checks its deposit amount.** `depositWithGas` and `prepareDepositWithGas` now reject a deposit amount that is not `0x`-prefixed hex with `InvalidHexStringError`; before, it ended in a native error or was sent as it was.
- **The `caller` members are no longer exposed.** `rootChainManager.caller`, `rootChain.caller` and the gas swapper's `caller` were marked `@internal` and documented as not part of the public API. They are now private and absent from the type declarations. If you were reaching through them, call the contract with your own client and the ABIs from `@polygonlabs/maticjs/abi`.
