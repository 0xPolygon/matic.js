---
'@polygonlabs/maticjs': minor
---

Contract reads are now validated against each contract's ABI, and a value that does not match fails with the new `AdapterResultMismatchError`. The SDK's own contract calls are also checked against the ABIs at compile time.

The transactions the SDK builds are byte-for-byte the same, and no existing API changes. Six things you could observe do change:

- **A malformed read now fails cleanly.** When a custom adapter returns a value that does not match the contract's ABI, the call rejects with the new `AdapterResultMismatchError`, exported from the package root. Its `info` names the `method`, the `field` (`<method>.<output name>`, or `<method>.<index>` when the ABI leaves the output unnamed), the `expectedType` the ABI declares and the `receivedType`, and it never has a `cause`. Its message says what was returned, for which output, what the ABI declares and what to do: a custom adapter is told what its `read()` must return, and a mismatch from the viem, ethers v5 or ethers v6 adapter, which should not happen with valid data, is to be reported as an issue against `@polygonlabs/maticjs`. Before, such a value could surface as a `TypeError`, a `SyntaxError` or a different SDK error, or be used as it was. A read now returns the same value on viem, ethers v5 and ethers v6, and a boolean read, such as an exists or approval check, accepts only a real boolean. The 4.0 staking reads that threw `BridgeEventDecodeFailedError` for a result that did not match the ABI now throw `AdapterResultMismatchError`; `BridgeEventDecodeFailedError` is still thrown for event, log, address-index and other on-chain or HTTP data that does not decode.
- **Some SDK errors no longer follow a malformed read.** `InvalidTokenTypeError`, `UntrustedPredicateError`, `InvalidHexStringError` (from the deposit-status read), `ExitQueueEmptyError`, `ExitGasLimitTooLowError` and `BurnTxNotCheckpointedError` could previously surface because a contract returned malformed data; they now surface as `AdapterResultMismatchError` in that case. Each is still thrown for its real condition, which is unchanged.
- **A custom `Adapter` sees a `bigint` for a few arguments.** Nothing on the wire changes (the calldata is identical on all three libraries), but `ReadRequest.args` and `WriteRequest.args` now carry a `bigint` where they carried a string or a number: the checkpoint id passed to the root chain's `headerBlocks` (three call sites), the index passed to an ERC-721 `tokenOfOwnerByIndex`, the `v` of the staking permit, and the amount passed to the gas swapper's `swapAndBridge`.
- **An ERC-721 index or a permit `v` that is not an integer is rejected up front.** `getTokenIdAtIndexForUser` and the staking `delegateWithPermit` and `prepareDelegateWithPermit` now reject a value that is not a non-negative safe integer (a fraction, `NaN`, `Infinity`, a negative number, or one past `Number.MAX_SAFE_INTEGER`) with `InvalidNumericValueError` before any request is sent. Before, the value was passed to the web3 library, which either failed with its own error or encoded a different number.
- **The gas swapper checks its deposit amount.** `depositWithGas` and `prepareDepositWithGas` now reject a deposit amount that is not `0x`-prefixed hex with `InvalidHexStringError`; before, it ended in a native error or was sent as it was.
- **The `caller` members are no longer exposed.** `rootChainManager.caller`, `rootChain.caller` and the gas swapper's `caller` were marked `@internal` and documented as not part of the public API. They are now private and absent from the type declarations. If you were reaching through them, call the contract with your own client and the ABIs from `@polygonlabs/maticjs/abi`.
